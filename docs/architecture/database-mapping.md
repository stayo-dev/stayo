# Purpose

This document defines the complete database architecture for StayO Version 1.

It serves as the bridge between the existing Shri Adithya backend database and the new StayO frontend.

The objectives are:

- Document all database entities.
- Map entities to frontend modules.
- Preserve compatibility with the existing backend.
- Identify reusable tables.
- Identify required schema extensions.
- Document relationships and constraints.
- Define data ownership.
- Standardize naming conventions.

This document is the database source of truth for frontend developers, backend developers, and AI implementation agents.

---

# Database Philosophy

StayO Version 1 will reuse the existing production database wherever possible.

The database has already been tested with real hostel operations and contains valuable business logic.

Schema changes should be:

- Additive
- Backward compatible
- Non-destructive

Avoid rewriting or replacing existing tables unless absolutely necessary.

# Row Level Security (RLS)

Version 1 uses Supabase RLS.

Policies should ensure:

Owner

Can access only their hostel.

Tenant

Can access only their own records.

Admin

Can access all records.

Future roles should extend existing policies.

# Database Migration Principles

Never delete production data.

Prefer additive migrations.

Test migrations on staging first.

Document every schema change.

Maintain rollback capability.

---

# Validation Rules

Database constraints should enforce:

Unique room numbers within a hostel.

Unique invitation tokens.

Valid foreign keys.

Required owner references.

Positive payment amounts.

Non-negative room capacities.

---

# Backup Strategy

Daily automated backups.

Retention according to Supabase plan.

Verify backup restoration periodically.

---

# Summary

The StayO database is designed to maximize reuse of the existing Shri Adithya backend while supporting future product growth.

Database changes should prioritize compatibility, data integrity, and minimal disruption to production operations.
